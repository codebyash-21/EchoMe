# EchoMe – Where the Data Comes From

EchoMe learns about the user from four places. Three are data people already produce; one is created by EchoMe itself. Every source is optional, and EchoMe still works with only voice and a phone.

| Source | What it captures | How it gets in |
|---|---|---|
| **Body** | Sleep, resting heart rate, steps, stress | Health Connect, Apple Health, or smartwatch export files |
| **Voice** | Check-ins, promises, why-clips, facts about the user | User speaks or types to EchoMe |
| **Activity** | App/site time, calendar, study sessions, commits | Local activity tracker, phone usage stats, calendar, GitHub |
| **Promise history** | Every promise: negotiated, kept, broken or moved, with the body/activity context at the time | Generated by EchoMe; the main input for the personal manual |

**Day 1:** the user imports past watch history (instant baselines) and does a 2-minute voice intro. By week 2, EchoMe also knows their promise patterns.

## About Me memory

- **Voice intro:** the user describes themselves (studies, goals, habits, weak spots, upcoming events). EchoMe sorts this into categories and shows *"Here's what I learned"* for confirmation before saving.
- **"Tell EchoMe" anytime:** lasting facts are kept; temporary ones (e.g. "interview on Friday") expire; old facts are updated rather than duplicated; "forget that" deletes by voice.
- **Said vs. data:** EchoMe gently points out mismatches, e.g. *"You said you're a night owl, but your best focus sessions this month were before noon. Update that?"*

## Linked apps: borrowed context

**Why linking exists**

- Promises need real context ("3 open TODOs in `backprop.py`").
- A commit can count as proof a promise was kept, with no manual logging.
- Video titles separate learning (tutorials) from distraction (Shorts).
- Career data anchors long-term goals.
- Links are temporary because always-on account access is creepy and risky.

**What each platform realistically allows**

| App | How it connects | Used for |
|---|---|---|
| GitHub | Live link: read-only OAuth, chosen repos, unlink anytime | Project context; commits as proof of kept promises |
| YouTube | Google Takeout watch-history import + phone screen time | Time spent; learning vs. distraction from titles |
| Instagram | Phone screen time + optional "Download your information" export | Time and timing of scrolling (no access to content) |
| LinkedIn | Data export or profile PDF | Long-term career goals and skills |

Instagram retired its API for personal accounts in December 2024, YouTube's API does not provide watch history, and LinkedIn's sign-in for ordinary apps shares only basic profile fields. Importing a file the user downloads themselves works today and keeps the data on the device.
